# What is SDLC?

**SDLC** stands for **Software Development Life Cycle**.

It is a **step-by-step process** used to develop high-quality software in a planned and organized way.

**Simple Definition:**
> **SDLC is a process that guides software development from planning to maintenance.**

**Example:**
Developing a **Library Management System**, **Online Shopping Website**, or **Banking Application** follows the SDLC process.

---

# Why is SDLC Used?

SDLC is used to:

- Plan software development
- Reduce development cost
- Improve software quality
- Complete projects on time
- Find and fix errors early
- Make software easier to maintain

---

# Phases (Process) of SDLC

## 1. Planning

In this phase, the project idea is discussed and planned.

**Activities:**
- Define project goals
- Estimate budget
- Estimate time
- Identify resources

**Example:**
Planning a Library Management System.

---

## 2. Requirement Analysis

Developers collect all customer requirements.

**Activities:**
- Meet with clients
- Gather requirements
- Prepare requirement documents

**Example:**
The library system should allow users to:
- Add books
- Issue books
- Return books

---

## 3. System Design

The software structure is designed before coding starts.

**Activities:**
- Design database
- Create system architecture
- Design user interface (UI)

**Example:**
Design login page, dashboard, and database tables.

---

## 4. Development (Coding)

Developers write the program code.

**Activities:**
- Write source code
- Build features
- Connect database

**Example:**
Using PHP, Java, Python, or C# to develop the application.

---

## 5. Testing

The software is tested to find and fix bugs.

**Activities:**
- Functional testing
- Performance testing
- Security testing
- Bug fixing

**Example:**
Check whether the login page works correctly.

---

## 6. Deployment

The completed software is released to users.

**Activities:**
- Install software
- Upload to server
- Make it available to users

**Example:**
Publishing a website online.

---

## 7. Maintenance

After deployment, the software is updated and maintained.

**Activities:**
- Fix bugs
- Improve performance
- Add new features
- Update security

**Example:**
Adding a new feature to an existing library system.

---

# Types of SDLC Models

## 1. Waterfall Model

- Development follows a fixed sequence.
- Each phase is completed before moving to the next.

**Best For:**
- Small projects
- Projects with fixed requirements

**Advantages:**
- Easy to understand
- Easy to manage

---

## 2. V-Model (Verification and Validation)

- Similar to the Waterfall Model.
- Testing is planned alongside every development phase.

**Best For:**
- Projects that require high quality
- Healthcare and banking software

**Advantages:**
- Early testing
- Better quality

---

## 3. Iterative Model

- Software is developed in small versions (iterations).
- Each version adds new features.

**Best For:**
- Projects with changing requirements

**Advantages:**
- Easy to improve
- Customer feedback after each iteration

---

## 4. Incremental Model

- Software is divided into smaller parts (increments).
- Each part is developed and delivered separately.

**Best For:**
- Large projects

**Advantages:**
- Faster delivery
- Easy testing

---

## 5. Spiral Model

- Combines development with risk analysis.
- Repeats planning, design, coding, and testing in cycles.

**Best For:**
- Large and high-risk projects

**Advantages:**
- Better risk management
- Flexible

---

## 6. Agile Model

- Software is developed in small, quick releases.
- Customers provide feedback regularly.

**Best For:**
- Modern software projects
- Mobile apps
- Web applications

**Advantages:**
- Fast development
- Flexible
- Frequent updates

---

## 7. Prototype Model

- A sample (prototype) is created first.
- Customers review it before full development begins.

**Best For:**
- Projects with unclear requirements

**Advantages:**
- Better understanding of requirements
- Reduces mistakes

---

## 8. RAD (Rapid Application Development) Model

- Focuses on quick software development using reusable components.

**Best For:**
- Small to medium projects
- Fast delivery

**Advantages:**
- Quick development
- Less coding time

---

## 9. Big Bang Model

- Development starts without much planning.
- Suitable only for very small projects.

**Best For:**
- Experimental or learning projects

**Advantages:**
- Simple
- No detailed planning required

**Disadvantages:**
- High risk
- Difficult to manage

---

# SDLC Models Comparison

| SDLC Model | Best For | Main Feature |
|------------|----------|--------------|
| Waterfall | Small projects | Sequential development |
| V-Model | High-quality systems | Testing in every phase |
| Iterative | Changing requirements | Repeat development cycles |
| Incremental | Large projects | Develop in small parts |
| Spiral | High-risk projects | Risk analysis |
| Agile | Modern software | Fast and flexible |
| Prototype | Unclear requirements | Sample system first |
| RAD | Fast development | Rapid delivery |
| Big Bang | Small experiments | Minimal planning |
